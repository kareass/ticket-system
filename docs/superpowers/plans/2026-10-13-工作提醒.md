# 工作提醒 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 新增一个完全独立的「工作提醒」模块（日期 / 提醒人 / 提醒内容 / 是否已完成），列表支持整行标红、勾选即保存、三态筛选，并接入首页卡片与左侧导航。

**Architecture:** 严格照抄既有模块的骨架 —— Prisma 单表 `Reminder`（无外键、无唯一约束）→ 两条 Route Handler（`/api/reminders` 与 `/api/reminders/{id}`）→ `src/types/index.ts` 加枚举与接口 → `helpers.ts` 加转发与序列化器 → axios 客户端 → Zustand 切片 → 三个页面 + 一个表单组件。**不碰**工单 / 需求 / 会议纪要的任何文件。

**Tech Stack:** Next.js 14 App Router + React 18 + TypeScript + antd 5 + Zustand + Prisma 5 / SQLite。

**依据文档：** `docs/superpowers/specs/2026-10-13-工作提醒-design.md`（本计划的每一处取舍都以该 spec 为准；发现冲突时**停下来报告**，不要自行改口径）。

## 前置事实（实施者必读，否则会踩坑）

| 事实 | 说明 |
|---|---|
| 断言基线 | **181**，本模块目标 **198**（`npm run api:smoke`） |
| 排序破例 | 工作提醒列表是**全站唯一**按 `date` **升序**的表；其余三个列表都是 `createdAt` 倒序。**不要为了「保持一致」改掉** |
| 勾选破例 | 列表勾选「已完成」直接 `PUT`，是全站唯一不经草稿门的写入，且**只限 `isDone` 这一个布尔字段** |
| 必填字段 | `remindee` / `content` 是必填，**不适用**「空串 = 清空」三态 —— 传空串一律 `400` |
| 无 409 | 本表没有任何唯一约束，**不写 `409` 分支**，也不要用 `isPrismaUnique` |
| 无事务 | 单表操作，**不要套 `$transaction`** |
| 日期口径 | 入库 `new Date(s + "T00:00:00.000Z")`（即 `toDayUtc`），出参 `toISOString().slice(0,10)`（即 `dayOnly`）。**绝不用** `new Date(s)` |
| 不碰的文件 | `src/components/MeetingForm.tsx`、`src/components/common/PersonSelect.tsx`、`src/lib/server/work-order-sync.ts`、`src/app/api/{work-orders,requirements,meetings}/**` |
| 控制台中文 | **绝不在命令行里敲中文发请求** —— Windows 控制台按 GBK 处理，到达 curl 时已是 U+FFFD，会得到**假故障**。可靠做法见 Task 7 |

**明确不做（写在这里是为了避免实施中被「顺手做了」）：**

1. **主动外发通知**（邮件 / 短信 / 企业微信）—— 架构不支持：无账号体系（不知道发给谁）、内网不出网、无后台定时进程。设计方案第八部分 Phase 2 的「邮件通知和提醒」属于未来的独立课题。
2. **周期 / 重复提醒**（每天、每周）—— 没有调度进程，重复规则只能靠查询时现算，复杂度远大于收益。
3. **完成时间的记录** —— 只存布尔量。
4. **「今日」与「已逾期」的区分** —— 需求方明确要求两者同一条规则（都标红）。
5. **关联工单 / 需求** —— 本模块与其它模块零关系。
6. **提醒人的动态候选人名**（会议纪要那套 `PersonSelect`）—— 明确改为固定下拉。
7. **列表内联编辑提醒内容** —— 只有「已完成」勾选是破例，文本仍走编辑页。
8. **种子数据加演示提醒** —— 保持冒烟脚本依赖的数据基线。
9. **计数接口** —— 首页卡片的未完成条数在本地算（数据量小，单开一个 `count` 路由是多余的路由）。

**未经验证的假设。实施时如发现与实际不符，先停下来报告，不要硬绕：**

1. **用户接受「打开页面看得见的待办标记」这个形态，而不是主动送达的通知。** 若实际期望是「到日子自动通知到人」，本方案从根上不成立，须重新设计。
2. **部门就是两个人（黄傲 / 陈婷婷），名单固定。** 若人员变动频繁，`REMINDEE_OPTIONS` 每次都要改代码，得先改设计文档改成维护型数据。
3. **数据量小（数百至数千条），前端过滤与本地计数够用。** 量级到万条以上时，前端过滤与首页本地计数都要改成下推 + 计数接口。
4. **`rowClassName` + `.reminder-row-overdue > td { color }` 能盖住 antd v5 的单元格配色。** **未实测** —— 退路见 Task 14 Step 2。
5. **首页卡片读 store 不会出现「0 条 → N 条」的闪烁。** **未实测** —— 已用 `remindersLoaded` 规避，见 Task 15。

**Windows 环境纪律：**
- dev server 运行时会锁住 `.next` → `npm run build` / `prisma generate` 报 **EPERM**，先停服。
- dev 的编译队列是串行的，一次编译被中断会让**后续所有请求一起卡住**（端口还在 LISTENING 但页面不返回）。处理：`netstat -ano | findstr :3000` 拿 PID → `taskkill //F //PID <PID>`（Git Bash 里开关要写成 `//F //PID`，单个斜杠会被 MSYS 当路径转换掉）。
- **不要运行 `npm run lint`**。

## Task 5: 列表与新建接口（`src/app/api/reminders/route.ts`）

**Files:**
- Create: `src/app/api/reminders/route.ts`

- [ ] **Step 1: 写入完整文件**

```ts
import { NextResponse } from "next/server";
import type { Prisma } from "@prisma/client";
import { prisma } from "@/lib/server/db";
import {
  apiError,
  asTrimmed,
  isValidCalendarDay,
  readJson,
  REMINDEES,
  toDayUtc,
  toReminderJson,
} from "@/lib/server/helpers";

export const runtime = "nodejs";

/**
 * GET /api/reminders
 * 工作提醒列表。三个可选筛选参数（可叠加）：
 *   ?isDone=true|false   三态：不传 = 全部；非法值（如 abc）同样视作不过滤，不报错
 *   ?remindee=黄傲        精确匹配；**值不在 REMINDEE_OPTIONS 内时视作不过滤**
 *                         （与工单/需求的 ?submittedBy 同一口径，不要改成返回空数组）
 *   ?keyword=xxx         子串匹配「提醒内容」
 *
 * ⚠️ 排序：**按 date 升序，同日按 createdAt 升序** —— 这是全站唯一一个不按
 * createdAt 倒序的列表。提醒的价值在「接下来要做什么」，最早的日期排最前，
 * 已逾期 / 今日到期的自然浮到顶部。不要为了「保持一致」把它改成倒序。
 */
export async function GET(req: Request) {
  const url = new URL(req.url);
  const isDoneRaw = url.searchParams.get("isDone");
  const remindee = url.searchParams.get("remindee")?.trim();
  const keyword = url.searchParams.get("keyword")?.trim();

  // 三态：只有字面量 "true" / "false" 才参与过滤，其余（不传、abc、空串）一律不过滤
  const isDone =
    isDoneRaw === "true" ? true : isDoneRaw === "false" ? false : undefined;

  const where: Prisma.ReminderWhereInput = {
    ...(isDone === undefined ? {} : { isDone }),
    ...(remindee && REMINDEES.includes(remindee) ? { remindee } : {}),
    ...(keyword ? { content: { contains: keyword } } : {}),
  };

  const rows = await prisma.reminder.findMany({
    where,
    // 同日必须给出第二排序键，否则 SQLite 不保证 tie 的稳定顺序（分页会抖）
    orderBy: [{ date: "asc" }, { createdAt: "asc" }],
  });
  return NextResponse.json(rows.map(toReminderJson));
}

/**
 * POST /api/reminders
 * 新建工作提醒。body：date*（YYYY-MM-DD）/ remindee*（枚举内）/ content*（非空）。
 * 返回 201 + 创建结果；校验失败 400 + details。
 * 本表无唯一约束，因此**不会**出现 409。
 */
export async function POST(req: Request) {
  const body = await readJson(req);
  if (!body) return apiError(400, "请求体必须是合法 JSON 对象。");

  const errors: string[] = [];

  const date = asTrimmed(body.date);
  if (!date || !isValidCalendarDay(date)) {
    errors.push("date 必填，格式 YYYY-MM-DD。");
  }

  const remindee = asTrimmed(body.remindee);
  if (!remindee) {
    errors.push("remindee（提醒人）必填。");
  } else if (!REMINDEES.includes(remindee)) {
    errors.push(`remindee 须为 ${REMINDEES.join(" / ")} 之一。`);
  }

  const content = asTrimmed(body.content);
  if (!content) errors.push("content（提醒内容）必填。");

  if (errors.length) return apiError(400, "参数校验失败。", errors);

  const created = await prisma.reminder.create({
    data: {
      date: toDayUtc(date as string) as Date,
      remindee: remindee as string,
      content: content as string,
    },
  });
  return NextResponse.json(toReminderJson(created), { status: 201 });
}
```

  toReminderJson,
} from "@/lib/server/helpers";

export const runtime = "nodejs";

// Next 14 的 params 是**同步对象**，不要 await
interface Ctx {
  params: { id: string };
}

/** GET /api/reminders/{id} —— 单条 */
export async function GET(_req: Request, { params }: Ctx) {
  const row = await prisma.reminder.findUnique({ where: { id: params.id } });
  if (!row) return apiError(404, "工作提醒不存在。");
  return NextResponse.json(toReminderJson(row));
}

/**
 * PUT /api/reminders/{id}
 * 局部更新。**必填字段不适用三态语义** —— 项目里「未传 = 不改 / 空串 = 清空 /
 * 非空 = 设为该值」那套只对**可选**字段成立（WorkOrder.remark、Meeting.recorder 等）。
 * remindee / content 是必填，空串只能是误操作或前端 bug，一律 400 打回。
 *
 * 列表页勾选「已完成」走的就是这个接口，且**只传 isDone** —— 这是全站唯一一处
 * 不经草稿门的写入（理由见设计文档 1.1：布尔开关没有中间态）。
 */
export async function PUT(req: Request, { params }: Ctx) {
  const body = await readJson(req);
  if (!body) return apiError(400, "请求体必须是合法 JSON 对象。");

  const existing = await prisma.reminder.findUnique({ where: { id: params.id } });
  if (!existing) return apiError(404, "工作提醒不存在。");

  const errors: string[] = [];
  const data: Prisma.ReminderUpdateInput = {};

  if (body.date !== undefined) {
    const date = asTrimmed(body.date);
    if (!date || !isValidCalendarDay(date)) {
      errors.push("date 格式须为 YYYY-MM-DD。");
    } else {
      data.date = toDayUtc(date) as Date;
    }
  }

  if (body.remindee !== undefined) {
    const remindee = asTrimmed(body.remindee);
    if (!remindee) {
      errors.push("remindee（提醒人）不能为空。");
    } else if (!REMINDEES.includes(remindee)) {
      errors.push(`remindee 须为 ${REMINDEES.join(" / ")} 之一。`);
    } else {
      data.remindee = remindee;
    }
  }

  if (body.content !== undefined) {
    const content = asTrimmed(body.content);
    if (!content) errors.push("content（提醒内容）不能为空。");
    else data.content = content;
  }

  // isDone：**false 是有效值，不是「不改」** —— 必须显式判 undefined，不能用 || 或 ??
  if (body.isDone !== undefined) {
    const isDone = asBool(body.isDone);
    if (isDone === undefined) errors.push("isDone 须为布尔值。");
    else data.isDone = isDone;
  }

  if (errors.length) return apiError(400, "参数校验失败。", errors);
  if (Object.keys(data).length === 0) {
    return apiError(400, "没有可更新的字段。");
  }

  const updated = await prisma.reminder.update({
    where: { id: params.id },
    data,
  });
  return NextResponse.json(toReminderJson(updated));
}

/** DELETE /api/reminders/{id} —— 无关联对象，直接删，返回 204 无响应体 */
export async function DELETE(_req: Request, { params }: Ctx) {
  const existing = await prisma.reminder.findUnique({ where: { id: params.id } });
  if (!existing) return apiError(404, "工作提醒不存在。");

  await prisma.reminder.delete({ where: { id: params.id } });
  return new NextResponse(null, { status: 204 });
}

 * 提醒列表的本地顺序必须与接口一致：date 升序，同日按 createdAt 升序。

function byReminderOrder(a: Reminder, b: Reminder): number {

  if (a.createdAt !== b.createdAt) return a.createdAt < b.createdAt ? -1 : 1;

}
