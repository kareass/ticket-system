---

## 第一部分：技术架构与技术栈

### 框架选择：Next.js（全栈 React 框架）

**为什么选 Next.js：**
- 前后端集成在一个框架，单一部署单元
- 内置 API 路由，无需另建后端
- 支持静态生成和服务端渲染，性能好
- 开发体验好，热更新快
- 内网部署友好，依赖清晰

### 技术栈详情

```
前端：
  - React 18+（UI框架）
  - Next.js 14+（全栈框架）
  - Ant Design 5（UI组件库，中文友好）
  - TailwindCSS（样式）
  - React Query（数据请求缓存）
  - Zustand（全局状态管理，轻量级）

后端：
  - Next.js API Routes（REST API）
  - Prisma（ORM，管理数据库操作）

数据库：
  - PostgreSQL 14+（推荐用于正式环境）
  - SQLite（开发/演示环境快速启动）

部署：
  - 直接服务器部署（单个 Node.js 进程 + pm2）
  - Git 代码管理（内网 Git 或 GitHub）
```

### 这个架构的优势

- 一个代码库管理前后端
- 一个部署单元
- 内网环境无需复杂配置
- 未来扩展可逐步分离

## 第二部分：功能设计与数据模型

### 数据模型

#### 工单表 (WorkOrder)
```
id: 唯一标识
date: 日期（必填，日期选择器，默认当天）
title: 标题（必填）
content: 工单内容（必填）
system: 系统（必填，下拉框，默认 WMS）
isConvertToRequirement: 是否转需求（布尔值）
requirementId: 关联的需求 ID（可为空，仅当 isConvertToRequirement=true 时填充）
requirementContent: 需求内容（同步自工单标题）
remark: 备注
createdAt: 创建时间
updatedAt: 更新时间
status: 工单状态（新建/已处理/已关闭等，预留扩展）
```

#### 需求表 (Requirement)
```
id: 需求 ID（必填，唯一）
date: 日期（必填，日期选择器，默认当天）
title: 需求标题
content: 需求内容
system: 系统（必填，下拉框，默认 WMS）
developmentDays: 开发时长（自动计算：从 date 到当前系统时间；若 isReleased=true，则为 date 到 releaseDate 的差）
currentNode: 当前节点（下拉框：方案中/开发中/测试中/已合并/已发布）
isUrgent: 是否加急（下拉框：是/否，默认否）
isReleased: 是否发版（布尔值）
releaseDate: 发版时间（日期选择器，仅当 isReleased=true 时必填）
remark: 备注
createdAt: 创建时间
updatedAt: 更新时间
workOrderId: 关联工单 ID（外键，一对一）
```

### 核心功能清单

| 功能模块 | 具体功能 |
|---------|--------|
| **工单管理** | 创建工单 / 编辑工单 / 删除工单 / 列表查看 / 搜索过滤 |
| **需求管理** | 手动创建需求 / 编辑需求 / 删除需求 / 列表查看 / 搜索过滤 |
| **数据同步** | 工单转需求（自动同步日期、标题等字段） |
| **字段验证** | 必填字段校验 / 日期格式验证 / 开发时长自动计算 |
| **修改提交流程** | 修改后需显式点击"提交"按钮才保存（防误操作） |
| **日期组件** | 所有日期字段采用日期选择器，默认当天 |
| **下拉框** | 系统、当前节点、是否加急等字段采用下拉选择 |
| **列表排序** | 双击列名排序，三态循环：升序 → 降序 → 取消（回到创建时间倒序）。需求列表可按 日期 / 开发时长 / 当前节点 / 是否加急 / 是否发版 / 发版时间 排；工单列表可按 日期 / 系统 / 状态 排。枚举字段按业务顺序（方案中 → 开发中 → 测试中 → 已合并 → 已发布）而非字符串序；空值无论升降序均排末尾 |
| **统计视图** | 预留工单统计、需求进度统计等看板 |

## 第三部分：部署方案

### 部署架构

```
1. 代码管理
   ├─ 内网 Git 服务（Gitea 或 GitLab 自建，或直接用 Git 裸库）
   ├─ 或使用公网 GitHub（如果可访问）
   └─ 本地分支管理：main(主分支) / develop(开发分支)

2. 部署步骤（直接服务器部署）
   ├─ Git 拉取最新代码
   ├─ 安装依赖（npm install）
   ├─ 编译构建（npm run build）
   ├─ 启动服务（npm start 或 pm2）
   └─ 验证部署成功

3. 部署位置
   └─ 内网服务器（单一部署单元）
```

### 直接服务器部署流程

```bash
# 在内网服务器上操作
cd /opt/wms-system
git clone <内网 Git 地址> .  # 或 git pull 更新

npm install                    # 安装依赖
npm run build                  # 编译构建
npm start                      # 启动服务（默认监听 3000 端口）

# 或用 pm2 保持后台运行
pm2 start "npm start" --name "wms-system"
```

### 部署所需的软件/工具清单

| Git | 最新 | 代码管理 |

## 第五部分：开发流程与工作流

### 标准开发工作流

1. **本地开发** → 2. **功能测试** → 3. **Git 提交** → 4. **部署到内网**

### 具体流程

```bash
# 1. 克隆项目到本地
git clone <Git 地址>
cd 四川物流工单系统

# 2. 安装依赖
npm install

# 3. 配置本地数据库
cp .env.example .env.local
# 编辑 .env.local，设置数据库连接

# 4. 运行数据库迁移
npx prisma migrate dev

# 5. 本地启动开发服务
npm run dev
# 访问 http://localhost:3000

# 6. 开发完功能后，提交到 Git
git add .
git commit -m "feat: 添加工单筛选功能"
git push origin main

# 7. 在内网服务器上部署
cd /opt/wms-system
git pull origin main
npm install
npm run build
npm start  # 或用 pm2 restart
```

### Git 分支策略（简化版）

- `main` - 主分支，直接部署到内网
- `develop` - 开发分支（可选，用于多人协作）
