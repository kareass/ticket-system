# 四川物流工单系统 — 部署指南

> 适用版本：v1.0.0（环节7 交付）
> 部署形态：单个 Node.js 进程（Next.js 全栈，前后端一体）+ 进程守护 pm2 + Git 拉取更新

---

## 一、环境要求

| 组件 | 版本 | 说明 |
|------|------|------|
| Node.js | **18.17 及以上**（`package.json` 已声明 `engines`） | 运行环境，推荐 20 LTS |
| npm | 随 Node 附带 | 项目含 `package-lock.json`，使用 `npm ci` 保证依赖一致 |
| Git | 任意近期版本 | 服务器拉取代码 |
| 数据库 | SQLite（默认，零配置）或 PostgreSQL 14+ | 见第四节 |
| pm2 | 最新 | 后台守护进程，可选但强烈建议 |

> 磁盘/内存参考：项目含 `node_modules` 约 500MB，构建期内存峰值约 1GB。

---

## 二、首次部署（服务器）

```bash
# 1. 拉取代码到目标目录
sudo mkdir -p /opt/scwos && sudo chown "$USER" /opt/scwos
git clone <内网 Git 地址> /opt/scwos
cd /opt/scwos

# 2. 生成并填写配置文件（SQLite 场景可直接用默认值）
cp .env.example .env
vi .env                      # 至少确认 DATABASE_URL

# 3. 一键部署
bash deploy.sh
```

`deploy.sh` 会依次完成：环境检查 → `git pull` → 校验 `.env` → `npm ci` → `prisma generate` + `prisma migrate deploy` → `npm run build` → `pm2 reload/start`。
脚本是**幂等**的，重复执行即为「更新发布」。

首次执行前若 `.env` 不存在，脚本会自动从模板生成并中止，提示你填写后重跑 —— 这是有意设计，避免用错数据库。

## 三、日常更新发布

```bash
cd /opt/scwos
bash deploy.sh                # 拉代码 + 装依赖 + 迁移 + 构建 + 平滑重载
```

指定分支/进程名：

```bash
DEPLOY_BRANCH=develop APP_NAME=scwos-dev bash deploy.sh
```

**回滚**：

```bash
git log --oneline -5           # 找到上一个可用提交
git checkout <commit>
bash deploy.sh                 # 重新构建并重载（会切回 detached HEAD，随后 git checkout main 复位）
```

## 四、数据库配置

### 方案 A：SQLite（默认，适合小规模内部使用）

```env
DATABASE_URL="file:./dev.db"
```

- 数据库文件位于 `prisma/dev.db`，**该文件即全部数据，务必备份**。
- 备份：`cp prisma/dev.db "backup/dev-$(date +%F).db"`（建议配 crontab 每日一次）。

### 方案 B：PostgreSQL（数据量大或需高可用时）

```env
DATABASE_URL="postgresql://USER:PASSWORD@HOST:5432/DBNAME?schema=public"
```

切换后需同步修改 `prisma/schema.prisma` 中 `datasource db` 的 `provider` 为 `postgresql`（当前为 `sqlite`），然后：

```bash
npx prisma migrate deploy      # 应用迁移建表
```

> 注意：SQLite 与 PostgreSQL 的迁移历史不通用，切换数据库属于一次性数据迁移动作，建议在项目尚未积累正式数据时完成。

### 数据库初始化脚本

```bash
bash scripts/db-init.sh                 # 建表（应用全部迁移）—— 生产首次部署用
bash scripts/db-init.sh --with-seed     # 建表 + 写入演示数据（会先清空现有数据）
bash scripts/db-init.sh --drop          # 重置数据库并重新迁移（二次确认，清空全部数据）
```

## 五、部署检查清单

部署前 / 部署后逐项确认。

### 5.1 部署前（在服务器执行一条命令即可）

```bash
npm run check:env
```

该脚本逐项输出 `[OK]/[WARN]/[FAIL]`，任一 `FAIL` 时以非 0 退出。检查项：

| # | 检查项 | 期望 |
|---|--------|------|
| 1 | Node.js 版本 ≥ 18 | OK |
| 2 | 项目目录可写（构建与 Prisma 生成需要） | OK |
| 3 | `node_modules` 已安装 | OK |
| 4 | `.env` 存在 | OK（生产必填） |
| 5 | `DATABASE_URL` 已配置且格式可解析 | OK |
| 6 | SQLite 场景下数据库文件存在 | OK / WARN（首次部署前允许 WARN） |
| 7 | Prisma Client 已生成 | OK |
| 8 | 数据库可连接且表结构就绪（回显工单/需求条数） | OK |
| 9 | 端口 `PORT`（默认 3000）可用 | OK / WARN（服务已在运行则属正常） |

> 安全说明：脚本只回显 `DATABASE_URL` 的**协议 + 主机 + 库名**，不会输出账号密码。

### 5.2 部署后验证

| # | 验证项 | 方法 | 期望 |
|---|--------|------|------|
| 1 | 进程存活 | `pm2 status` | `online`，重启次数无异常增长 |
| 2 | 端口监听 | `ss -lntp \| grep 3000` | 有 LISTEN |
| 3 | 首页可达 | 浏览器打开 `http://<服务器IP>:3000` | 显示系统首页与两张功能卡片 |
| 4 | 工单列表 | 打开「工单管理」 | 列表加载，无报错弹窗 |
| 5 | 需求列表 | 打开「需求管理」 | 同上 |
| 6 | 写操作 | 新建一条工单并提交 | 提交成功提示，列表出现新记录，刷新后仍在 |
| 7 | 转需求 | 对刚建的工单点「转需求」 | 提示已生成 `R-年份-序号`，两表状态联动 |
| 8 | 接口健康 | `curl -s http://127.0.0.1:3000/api/work-orders` | 返回 JSON 数组 |
| 9 | 持久化 | `pm2 restart` 后刷新页面 | 数据仍在 |
| 10 | 日志无异常 | `pm2 logs --lines 50` | 无未捕获异常堆栈 |

### 5.3 接口冒烟（可选，更严格）

后端 API 全套自动化断言（53 项，含数据自清理）：

```bash
npm run api:smoke
```

## 六、常见问题 FAQ

**Q1：`npm ci` 报错或依赖装不上？**
确认 Node 版本 ≥ 18.17（`node -v`）。内网无外网时需配置 npm 私服：`npm config set registry http://<私服地址>/`，或使用离线镜像拷贝 `node_modules`。

**Q2：`prisma migrate deploy` 报 `P1001: Can't reach database server`？**
PostgreSQL 场景：确认库已启动、`.env` 中主机/端口/账号正确、服务器防火墙放行 5432。SQLite 场景一般不会出现，多为 `DATABASE_URL` 路径写错。

**Q3：启动后浏览器打不开页面？**
① `pm2 logs` 看是否启动失败；② 确认端口：`PORT` 未设置时默认 3000；③ 服务器安全组/防火墙放行该端口；④ 仅内网访问时确认客户端在同一网段。

**Q4：页面能开但列表一直转圈、控制台报 500？**
多为数据库未初始化。执行 `npm run check:env` 定位；若提示表结构不就绪，执行 `npx prisma migrate deploy`。

**Q5：`npm run build` 失败，报 `.next` 相关 EPERM / 文件被占用（Windows）？**
开发服务器正在运行会占用 `.next` 目录。生产构建请先停掉 dev server；如需在 dev 运行期间做隔离构建验证，可用 `NEXT_DIST_DIR=.next-build npm run build`（已内置支持，`.next-build` 已被 git 忽略）。

**Q6：构建期内存不足（OOM，常见于 1GB 小内存机）？**
`NODE_OPTIONS=--max-old-space-size=1536 npm run build`，或临时加 swap。

**Q7：忘记 `requirementId` 唯一约束，出现「编号已存在」？**
需求编号 `R-年份-序号` 全局唯一。手工新建时若提示冲突，改一个编号；「转需求」由系统自动生成，不会撞号。

**Q8：想清空演示数据、重新开始？**
`npx prisma migrate reset --force`（会清库并重放迁移）或 `bash scripts/db-init.sh --drop`。

**Q9：如何修改端口？**
`.env` 中设置 `PORT=3001`，重新 `bash deploy.sh`。

**Q10：pm2 开机自启？**
`pm2 startup` 生成命令并按其提示执行一次，随后 `pm2 save`。

**Q11：`.env` 要不要提交到 Git？**
**不要**。`.env` 已在 `.gitignore` 中；仓库只保留 `.env.example` 模板。API 密钥类信息不得写入任何文档或提交记录。
