# 四川物流工单系统 — 用户手册

> 面向使用者：部门内登记工单、跟进需求的同事。
> 系统无需注册登录，打开浏览器访问地址即可使用。

---

## 一、系统是做什么的

一句话：**把部门里的工作工单登记下来，再把需要开发的需求从工单转化出来，一路跟到发版。**

两条主线：

```
工单（WorkOrder）：日常工作的登记与追踪
  └─ 需要开发的，一键「转需求」→

需求（Requirement）：跟方案 → 开发 → 测试 → 合并 → 发布
```

页面只有三个入口：**首页**（导航）、**工单管理**、**需求管理**。

---

## 二、访问系统

在浏览器打开管理员提供的地址，例如 `http://192.168.1.100:3000`。

推荐使用 Chrome / Edge 最新版。系统适配了窄屏，但表格列较多，**建议在 1440 宽以上窗口使用**，体验最佳。

## 三、工单管理

### 3.1 查看工单列表

顶部导航点击「工单管理」。

列表列含义见 [5.1 工单字段说明表](#51-工单字段说明表-workorder)。

### 3.2 新建工单

1. 点击左上角 **「新建工单」**；
2. 填写表单（带 <span style="color:red">*</span> 为必填）：

| 字段 | 是否必填 | 默认值 | 说明 |
|------|---------|--------|------|
| 日期 | ✅ | **自动填今天** | 日期选择器 |
| 标题 | ✅ | 空 | 一句话概括 |
| 工单内容 | ✅ | 空 | 详细描述 |
| 系统 | ✅ | WMS | 下拉：WMS / ERP / OMS / TMS / 其他 |
| 状态 | ✅ | 新建 | 下拉：新建 / 已处理 / 已关闭 |
| 是否转需求 | ❌ | 否 | 开关。开启后下方两个字段才可填，保存即按「需求ID」**立即创建需求** |
| 需求ID | 条件必填 | 空 | 业务编号，需唯一（如 `R-2026-001`）。**仅在开启「是否转需求」后可填**；开启后必填，不填不能保存 |
| 需求内容 | ❌ | 空 | 仅在开启「是否转需求」后可填；转需求时带到需求表，**留空即需求内容为空**（不会自动取标题） |
| 备注 | ❌ | 空 | 补充信息 |

3. 点击 **「提交」** 保存；点「取消」放弃返回列表。

> 保存成功后会回到列表并出现「创建成功」提示。

### 3.3 编辑工单

两种方式：

- **整条编辑**：列表操作列点「编辑」，改完点「提交」；
- **列表内快捷修改**：直接在列表里改「系统 / 状态」这两个字段 —— 这类修改**不会立即保存**，会先变成待提交状态（单元格上有标记，左侧「提交」按钮出现数字，如「提交（2）」表示 2 条待提交）。

> 「是否转需求」在列表里是**只读标签**（是 / 否），不能在列表直接改 —— 它由「转需求」操作驱动，避免出现标记与实际需求不一致的情况。

> ⚠️ **这是本系统的核心规则：改完必须点「提交」并确认，才会写入数据库。**
> 忘记点提交就切换页面，修改会丢失。
> 点「还原」可一次性放弃所有未提交的改动。

### 3.4 搜索与筛选

- **按标题搜索**：右上角输入框，实时过滤（不区分大小写）；
- **按系统筛选**：右上角下拉框，可清空；
- 两者可叠加使用。

### 3.5 转需求（最常用的功能）

**需求ID 是转需求的依据，必须填写**。有两种操作方式，效果相同：

**方式一：列表点「转需求」，在弹框里填（推荐）**

1. 在工单列表该行操作列点 **「转需求」**；
2. 弹框里有两个字段：
   - **需求ID**（必填）：如 `R-2026-004`。如果这张工单上之前登记过编号，弹框会**自动回填**，可以直接用或改掉；编号没填时「转为需求」按钮是灰的；
   - **需求内容**（选填）：描述需求背景与验收期望。**留空则转出的需求内容也为空**（系统不会拿工单标题去填）。
3. 点 **「转为需求」**。

**方式二：在编辑页开启开关，保存即转**

1. 该行操作列点 **「编辑」**；
2. 把 **「是否转需求」** 打开 —— 打开后下方的 **「需求ID」「需求内容」才能填写**（未开启时是灰的，不可填）；
3. 填 **「需求ID」**，需要的话再填 **「需求内容」**（不填就是空，系统不会自动填标题）；
4. 点 **「提交」**——保存的同时系统就在需求表建好了这条需求。

> 💡 两种方式选一种即可。只填需求ID、不打算现在建需求的情况已经不需要了：直接留空，等要转的时候在弹框里填。

无论哪种方式，系统都会自动完成：

- 按**你填写的需求ID**在需求表创建需求（编号撞号会提示「已被占用」，需更换）；
- 把工单的**日期、标题、内容、系统**同步到需求（标题取工单标题；内容取你填的「需求内容」，**没填就是空**，不会自动取标题）；
- 需求的初始节点设为 **方案中**，开发时长按「日期 → 今天」自动计算；
- 工单的「是否转需求」置为 **是**，「转需求」按钮变为禁用，防止重复转换。

> 一条工单最多转出一条需求（一对一）。若提示「该工单已转需求」，说明此前已转换过。
> 若提示「请填写「需求ID」后再转需求」，说明弹框里的编号是空的 —— **不填需求ID 不能完成转需求**。
> 需求ID 已存在会提示「已被占用」，换一个编号即可（需求ID 全局唯一）。
> 转需求后仍可修改编号：在编辑工单页改「需求ID」并提交，关联需求的编号同步变更（撞号会被拒绝）。

### 3.5.1 改变需求编号 / 取消转需求

- **改编号**：在编辑工单页修改「需求ID」并提交，关联需求的编号同步变更。
- **取消转需求**：不能直接在工单上关闭开关（会提示先删除关联需求）。请到「需求管理」删除那条需求，工单的「是否转需求」会自动复位为「否」，而**工单上登记的需求ID 会保留**（列表中显示为灰色标签），方便你点「转需求」按原编号重建（弹框会自动回填这个编号）。

### 3.6 删除工单

操作列点「删除」并确认。

> ⚠️ **已转为需求的工单不能直接删除**。系统会提示「该工单已转为需求（R-…），请先删除关联需求再删除工单。」
> 这是为了保护数据一致性：需求还在跟进，来源工单不该凭空消失。

### 3.7 自定义列的显示顺序与宽度

- **拖动列标题**可调整列顺序；**拖动列边界**可调整列宽；
- 系统会**记住你的列布局**，下次打开仍然生效（保存在本机浏览器中，换电脑不通用）；
- 想恢复原样，点击表格上方的 **「还原默认列布局」**。

### 3.8 按字段排序

**双击列名**即可排序，连续双击同一列会循环切换三种状态：

| 双击次数 | 结果 | 列名左侧的标记 |
|---------|------|--------------|
| 第 1 次 | 升序（由小到大） | ▲（蓝色） |
| 第 2 次 | 降序（由大到小） | ▼（蓝色） |
| 第 3 次 | 取消排序，回到默认的创建时间倒序 | ⇅（灰色） |

列名左侧带灰色 ⇅ 标记的列都可以双击排序：

| 列表 | 可排序的列 |
|------|-----------|
| 工单列表 | 日期、系统、状态 |
| 需求列表 | 日期、开发时长、当前节点、是否加急、是否发版、发版时间 |

几点说明：

- 「当前节点」按**业务流程顺序**排，不是按文字拼音：升序是 方案中 → 开发中 → 测试中 → 已合并 → 已发布；
- 「开发时长」「发版时间」**没有值的记录始终排在最后**，升序降序都一样；
- **排序只改变显示顺序，不会改动任何数据**，也不会触发保存；
- 如果你有**改过但还没点「提交」**的内容，排序按已提交的值计算，那一行不会因为临时修改而跳走；提交后才会移动到新位置；
- 双击列名是排序，**拖动列名是调整列顺序**，两者互不影响。

### 3.9 刷新数据

列表数据有缓存，页面来回切换**不会重复请求**。
需要看最新数据时，点右上角 **「刷新」**。

## 四、需求管理

### 4.1 查看需求列表

顶部导航点击「需求管理」。需求的来源有两种：**工单转来的**（显示来源工单标签）和**手工新建的**。

### 4.2 手工新建需求

点击「新建需求」，填写表单：

| 字段 | 是否必填 | 默认值 | 说明 |
|------|---------|--------|------|
| 日期 | ✅ | **自动填今天** | 需求提出日期 |
| 需求ID | ✅ | 空 | **全局唯一**，如 `R-2026-010`；重复会提示「编号已存在」 |
| 需求标题 | ❌ | 空 | |
| 需求内容 | ❌ | 空 | |
| 系统 | ✅ | WMS | 下拉选择 |
| 当前节点 | ✅ | 方案中 | 下拉：方案中 / 开发中 / 测试中 / 已合并 / 已发布 |
| 是否加急 | ✅ | 否 | 加急需求在列表中显示红色标签 |
| 是否发版 | ✅ | 否 | 选「是」时下方出现 **发版时间**（必填，默认今天） |
| 备注 | ❌ | 空 | |
| 开发时长 | 自动 | — | **只读**，见 4.5 |

### 4.3 编辑需求

- **整条编辑**：操作列点「编辑」；
- **列表内快捷修改**：「系统 / 当前节点 / 是否加急 / 是否发版」可直接改，同样需要点 **「提交」** 才保存。

关于「是否发版」的提醒：
- 从 **否 → 是**：系统自动把**发版时间填为今天**（可再去编辑页改成实际发版日）；
- 从 **是 → 否**：**发版时间会被清空**，开发时长改回按「今天」计算。

### 4.4 搜索与筛选

- **按需求ID/标题搜索**：右上角输入框；
- **按当前节点筛选**：右上角下拉框，例如只看「测试中」。

### 4.5 开发时长怎么算的

**自动计算，不可手工填写**（手工填的值会被系统忽略）：

| 情形 | 计算方式 |
|------|---------|
| 未发版 | 需求日期 → **今天** |
| 已发版 | 需求日期 → **发版时间** |

两端**含当天**，结果为 0 时显示 0（不会出现负数）。

> 例：日期 2026-08-01，今天 2026-09-10，未发版 → 开发时长 40 天。

### 4.6 删除需求

操作列点「删除」并确认。若该需求来自工单，删除后**来源工单的「是否转需求」会自动复位为「否」**（工单上的需求ID/需求内容保留），该工单便可按原编号重新转需求或直接删除。

## 六、操作速查（常见问题）

**Q：我改了列表里的下拉框，切到别的页面回来发现没变？**
内联修改必须点左侧 **「提交」** 按钮并在弹窗中确认才会保存。这是系统的防误操作设计。

**Q：提交时提示「请先处理…」或红色错误？**
错误提示会写明原因，例如编号重复、工单已转需求。按提示调整后重试即可。

**Q：删不掉工单，提示要先删除关联需求？**
先到「需求管理」找到对应需求（列表「来源工单」列可识别）删除，再删工单。

**Q：编辑工单时「需求ID」是灰的，填不了？**
这是设计如此：需求ID 只在「是否转需求」开关打开后才可填。要填它就先打开开关；如果只是想转需求而不想动开关，直接用列表操作列的「转需求」，在弹框里填编号即可。

**Q：点「转需求」后弹框里「转为需求」按钮是灰的？**
说明需求ID 还是空的。需求ID 是转需求的依据、必填，填上编号后按钮就会变成可点。

**Q：保存工单时提示「需求ID R-xxxx 已被占用」？**
该编号在需求表里已存在（需求ID 全局唯一）。换一个编号，或到需求列表确认这条需求是否已经建过。

**Q：想关掉「是否转需求」开关，但它是灰的 / 提示不能关闭？**
该工单已经转出需求了。请先到「需求管理」删除对应需求，工单的开关会自动复位；工单上登记的需求ID 会保留，可点「转需求」按原编号重建。

**Q：需求开发时长看起来不对？**
检查「日期」「是否发版」「发版时间」三项。时长由它们自动推导，不能手工改。

**Q：列表列的顺序乱了 / 想恢复原样？**
点表格上方的「还原默认列布局」。

**Q：怎么让列表按日期或开发时长排？**
双击那一列的列名。连续双击三次依次是 升序 → 降序 → 取消。列名左侧带灰色 ⇅ 的列都可以双击排序。「当前节点」按业务流程顺序排而非拼音序；「开发时长」「发版时间」没有值的始终排在最后。详见 3.8。

**Q：数据是别人刚录的，我这边没看到？**
点右上角「刷新」。

**Q：误删了数据能恢复吗？**
删除不可撤销，需联系管理员从数据库备份恢复。请谨慎操作。

**Q：能两个人同时改同一条记录吗？**
可以，但**后提交的会覆盖先提交的**。建议同一条记录由同一人维护。

### 7.1 想新增一个下拉选项（如系统里多一个「SRM」）

系统的所有下拉选项都收在**一个文件**里：`src/types/index.ts`。改一处，表单下拉、列表内联下拉、
筛选框、以及后端对枚举的校验会**同时生效**。

1. 打开 `src/types/index.ts`，找到要改的数组，加一行：

```ts
export const SYSTEM_OPTIONS = ["WMS", "ERP", "OMS", "TMS", "其他", "SRM"] as const;
```

2. 如果该选项要参与配色，在下方同名的配色表里补一行（漏补会**编译报错**，不会静默失效）：

```ts
export const SYSTEM_COLORS: Record<string, string> = {
  // ……原有项…
  SRM: "geekblue",
};
```

3. 重新构建并启动：

```powershell
npm run build
npm run start
```

**不需要改数据库、不需要迁移** —— 这些字段在库里是普通文本列，不是数据库枚举，历史数据不受影响。

| 想改的下拉框 | 改哪个数组 |
|-------------|-----------|
| 系统（工单 / 需求共用） | `SYSTEM_OPTIONS` |
| 工单状态 | `WORK_ORDER_STATUS_OPTIONS` |
| 需求当前节点 | `NODE_OPTIONS` |

> ⚠️ **需求节点**的五种取值写死在《设计方案》里，「方案中 → 开发中 → 测试中 → 已合并 → 已发布」
> 是业务流程的定义，增删节点属于需求变更 —— 请先由负责人改设计文档，再改代码。
> 系统、工单状态两类没有这个限制，可直接增删。
>
> 另：`是否加急`、`是否发版` 是固定的「是 / 否」，定义在同文件的 `YES_NO_OPTIONS`。
