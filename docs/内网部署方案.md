# 四川物流工单系统 — 内网（离线）部署方案

> 适用版本：v1.0.0
> 适用场景：**无外网或外网受限**的内网环境 —— 部门内网、专网、生产隔离网。
> 配套文档：[部署指南.md](./部署指南.md)（常规在线部署 / FAQ）、[用户手册.md](./用户手册.md)（使用说明）。

---

## 一、结论先行

**系统运行期零外网依赖**（已实测，见 1.1）。整个交付流程里只有「装依赖」和「构建」两个动作需要外网 ——
本方案把它们整体挪到**一台能上网的准备机**上完成，目标机（内网机）从此不需要任何外网。

### 1.1 实测依据（2026-09-14，内网环境实机验证）

| 检查项 | 实测结果 |
|--------|---------|
| 服务进程持有的外网连接 | **无** —— 只有 `0.0.0.0:3000` 监听，无任何外部地址连接 |
| 页面 HTML 中的外部引用 | **0 个**（字体走系统字体，未使用 Google Fonts / CDN） |
| CSS 产物中的外链字体 | 无 `@font-face` / `@import` 外部字体 |
| 前端调用后端的地址 | 相对路径 `/api`（`NEXT_PUBLIC_API_BASE_URL` 留空）—— 换任何 IP 都不需改代码 |
| 服务监听地址 | `0.0.0.0:3000`，用非 localhost 的内网地址访问实测返回 200 |
| Prisma 查询引擎 | 已落地本地 `node_modules`（19MB `.dll`），**运行时不下载** |
| 数据库 | SQLite 本地文件 `prisma/dev.db` |
| `src/` + `prisma/` + `scripts/` 全量外网 URL 扫描 | **0 个** |

> 构建产物里会出现 `fonts.googleapis.com`、`use.typekit.net` 等字符串，那是 Next.js 运行时**自带的
> 「已知字体域名白名单」常量**，只有在代码里使用 `next/font/google` 时才会真正去加载。本项目未使用，
> 返回的 HTML 里一个外链都没有。

### 1.2 各环节的外网需求一览

| 环节 | 需要外网？ | 本方案如何处理 |
|------|-----------|---------------|
| `npm ci` 装依赖 | **需要** | 挪到准备机；目标机直接用随包携带的 `node_modules` |
| `prisma generate`（下载查询引擎） | **需要** | 同上；引擎已随包携带（见 2.3 的坑） |
| `npm run build` 构建 | 不需要（依赖装好后纯本地） | 挪到准备机；目标机用随包携带的 `.next` |
| `npm run start` 运行 | **不需要** | 目标机直接启动 |
| 浏览器访问 / 增删改查 | **不需要** | 内网直连 |
| 数据库读写 | **不需要** | SQLite 本地文件 |

## 二、方案选型

### 2.1 三种方案对比

| 方案 | 适用场景 | 目标机外网需求 | 复杂度 |
|------|---------|---------------|--------|
| **A. 离线整包投递**（推荐） | 目标机完全不能上外网 | 无 | ★ 低 |
| **B. 内网源直装** | 内网有 npm 私服，且私服能代理 Prisma 二进制 | 无（但需私服） | ★★ 中 |
| **C. 内网 Git + 离线依赖** | 代码需持续从内网 Git 更新 | 无（但需 Git 私服） | ★★ 中 |

### 2.2 为什么推荐方案 A

- 只有一次性准备工作，之后**每次更新都只是换一个包**，不依赖任何私服配置；
- 不要求目标机有 npm / Git，**只要求装一个 Node.js**（离线 `.msi` 拷过去即可）；
- 构建与运行在同一套产物上完成，**不存在「构建机与目标机环境不一致」的问题**；
- 已在本项目当前环境实机验证通过（见 1.1）。

> 若你们内网已有成熟的 npm 私服，且确认它能代理 Prisma 二进制，方案 B 也很顺；否则请用 A。

### 2.3 ⚠️ 必读：Prisma 查询引擎的坑

`npm ci` 会触发 `postinstall` 的 `prisma generate`，而 `@prisma/engines` 的安装脚本会去
**`binaries.prisma.sh`** 下载数据库查询引擎（本机为 19MB 的 `query_engine-windows.dll.node`）。

**关键在于：公司内网的 Nexus / Verdaccio 一类私服通常只代理 npm 包，不代理这个二进制源。**
典型症状是「几百个包都装上了，偏偏 `prisma generate` 失败」，且报错看起来像网络超时。

三种应对（方案 A 天然规避此问题）：

1. **用方案 A** —— 引擎已随 `node_modules` 携带，目标机不执行 `npm ci`，根本不会触发下载；
2. 配置引擎镜像：`PRISMA_ENGINES_MIRROR=http://<内网地址>/prisma-engines`（内网需自建该镜像）；
3. 从能上网的机器把 `node_modules/.prisma/` 与 `node_modules/@prisma/engines/` 两个目录整个拷进去。

## 三、方案 A：离线整包投递（推荐）

### 3.1 准备机（能上网的机器）操作

确认 Node.js ≥ 18.17（推荐 20 LTS），然后：

```bash
cd "E:/ai/claude code/四川物流工单系统"

npm ci            # 装依赖（会自动 prisma generate，含下载查询引擎）
npm run build     # 生产构建

# 可选：写入演示数据。注意会先清空现有数据，正式投递请跳过
# npm run db:seed
```

### 3.2 打包

先删掉构建缓存 —— 它占 478MB 且**运行时完全不需要**：

```bash
rm -rf .next/cache
```

然后打成压缩包（排除本机专属与敏感文件）：

```bash
cd "E:/ai/claude code/四川物流工单系统"
tar -czf ../scwos-offline-v1.0.0.tar.gz \
  --exclude=.git \
  --exclude=_dispatch \
  --exclude=mattpocock-skills \
  --exclude=.env \
  --exclude='prisma/dev.db' \
  --exclude='*.xlsx' \
  --exclude='*.csv' \
  --exclude=tsconfig.tsbuildinfo \
  .
```

**体积参考**（实测）：

| 项 | 体积 | 是否入包 |
|----|------|---------|
| `node_modules/`（含 Prisma 查询引擎 19MB） | 577 MB | ✅ 必须 |
| `.next/`（剔除 `cache/` 后：`server/` 2.2MB + `static/` 1.9MB + 其余） | 约 4 MB | ✅ 必须 |
| `.next/cache/` | 478 MB | ❌ 已删（运行时不需要） |
| 源码 + 文档 + 脚本 | 约 0.3 MB | ✅ 排障需要 |
| **打包前合计** | **约 581 MB** | gzip 后约 180~200 MB |

> **同一局域网内传输建议直接拷文件夹**（不压缩），几百 MB 走千兆网几十秒就完事；
> gzip 这一步反而要花几分钟。用移动介质 / 跨网段时才值得压缩。

### 3.3 投递

把包（或整个目录）拷到目标机，例如放到 `D:\scwos\`。

### 3.4 目标机操作

1. 装 **Node.js 18.17+**（离线：把 `.msi` 安装包一并拷过去，双击安装，保持勾选 *Add to PATH*）。
   目标机**不需要** npm 联网、**不需要** Git。
2. 解包到目标目录，例如 `D:\scwos`：

```powershell
cd D:\
tar -xzf scwos-offline-v1.0.0.tar.gz -C D:\scwos
```

3. 生成配置文件：

```powershell
cd D:\scwos
Copy-Item .env.example .env
notepad .env
```

`.env` 内网最小配置：

```env
DATABASE_URL="file:./dev.db"
PORT=3000
NEXT_PUBLIC_API_BASE_URL=
NEXT_TELEMETRY_DISABLED=1
```

4. （仅当包内未带 `dev.db` 时）建库：

```powershell
npx prisma migrate deploy
```

5. 启动：

```powershell
npm run start
```

浏览器打开 `http://localhost:3000`。

### 3.5 验证

```powershell
npm run check:env     # 环境检查清单，逐项 OK/WARN/FAIL（纯本地，不联网）
npm run api:smoke     # 后端接口冒烟，107 项断言（服务需已在 3000 运行）
```

> `api:smoke` 运行结束会自动清理本轮测试数据，可放心执行。

## 四、方案 B：内网源直装

适用：目标机能连内网 npm 私服，且私服已代理 Prisma 二进制（或另有引擎镜像）。

### 4.1 配置内网源

```bash
npm config set registry http://<内网私服地址>/
```

项目内可固化（可选，在项目根建 `.npmrc`）：

```ini
registry=http://<内网私服地址>/
```

### 4.2 处理 Prisma 引擎（见 2.3）

```bash
export PRISMA_ENGINES_MIRROR=http://<内网地址>/prisma-engines     # Linux
# Windows PowerShell：$env:PRISMA_ENGINES_MIRROR="http://<内网地址>/prisma-engines"
```

若内网没有引擎镜像，就从能上网的机器把 `node_modules/.prisma/`、`node_modules/@prisma/engines/`
两个目录拷进目标机的 `node_modules` 对应位置 —— 这是最省事的绕法。

### 4.3 安装、构建、启动

```bash
cd /opt/scwos
npm ci
npx prisma migrate deploy
npm run build
npm run start          # 或 pm2 start npm --name scwos -- start
```

## 五、方案 C：内网 Git + 离线依赖（代码需持续更新时）

适用于「代码在内网 Git 服务器上维护、要按提交更新」的场景。思路：**代码走 Git，依赖与构建不重做**。

```bash
# 内网 Git 服务器（或 GitLab 内网部署）上建裸库，从准备机推代码
git remote add origin git@<内网Git地址>:scwos.git
git push -u origin main
```

目标机首次用方案 A 的整包落地；此后每次更新：

```bash
cd /opt/scwos
git pull                                    # 只更新源码
# 依赖没变 → 直接复用现有 node_modules
npm run build
pm2 reload scwos
```

**只要 `package.json` 有改动**（新增/升级依赖），就必须回到准备机重做一次整包，按方案 A 投递 ——
因为目标机装不了新依赖。这一点务必在变更流程里守住。

## 六、Windows 目标机收尾（必做）

### 6.1 关闭遥测

Next.js 默认开启匿名遥测，会尝试连 `telemetry.nextjs.org`。内网连不上**不会导致崩溃**（非阻塞），
但会让 `next build` 卡在超时等待、日志出现噪音。建议永久关闭：

```powershell
# 写入用户级环境变量，重启终端后生效
[Environment]::SetEnvironmentVariable("NEXT_TELEMETRY_DISABLED","1","User")
```

### 6.2 放行防火墙端口（其他机器要访问时）

服务默认监听所有网卡，但 **Windows 防火墙默认会拦下其他机器的入站连接**。
以**管理员身份**打开 PowerShell，执行一次：

```powershell
New-NetFirewallRule -DisplayName "SCWOS 3000" -Direction Inbound -Protocol TCP -LocalPort 3000 -Action Allow
```

查本机地址（**用那个 `192.168.x.x` / `10.x.x.x` 的物理网卡地址**）：

```powershell
ipconfig
```

> ⚠️ 如果你的机器上装了 VirtualBox / VMware，`ipconfig` 里还会出现 `192.168.56.1`、`192.168.xxx.1`
> 这类**虚拟网卡地址** —— 同事用那个地址是连不上的，别给错。

### 6.3 开机自启（可选）

- **简单做法**：新建 `启动系统.bat`（内容见[部署指南 4.4](./部署指南.md)）放进「启动」文件夹
  （`Win + R` 输入 `shell:startup`），登录后自动运行。
- **正规做法**：用 [NSSM](https://nssm.cc/) 注册为 Windows 服务，开机即启、崩溃自动重启，无需登录桌面。

### 6.4 启动脚本模板

```bat
@echo off
chcp 65001 >nul
cd /d "D:\scwos"
echo 正在启动四川物流工单系统，请勿关闭本窗口...
npm run start
pause
```

## 八、更新与回滚

### 8.1 更新（方案 A）

1. 准备机：更新代码 → `npm ci`（若依赖有变）→ `npm run build` → `rm -rf .next/cache` → 重新打包；
2. 目标机：停止服务 → **备份数据**（见第九节）→ 用新包覆盖 `node_modules/`、`.next/`、`src/`、`prisma/migrations/`；
3. 若 `prisma/migrations/` 有新增：执行 `npx prisma migrate deploy`；
4. 启动并走一遍第七节清单。

> **不要覆盖 `prisma/dev.db` 与 `.env`** —— 那是目标机的数据与配置。

### 8.2 回滚

保留上一个版本的完整包（或至少保留旧 `node_modules/` + `.next/`），出问题时整体换回即可。
数据库若经历了迁移，回滚时需一并还原备份的 `dev.db`。

## 九、备份

**SQLite 场景下 `prisma/dev.db` 这一个文件就是全部数据。**

```powershell
# Windows：停止服务后复制
Copy-Item prisma\dev.db "backup\dev-$(Get-Date -Format yyyy-MM-dd).db"
```

```bash
# Linux：建议配 crontab 每日一次
cp prisma/dev.db "backup/dev-$(date +%F).db"
```

> 备份前先停服（或至少确认无写入），避免拷到写了一半的文件。

## 十、内网专有 FAQ

**Q1：目标机完全不能上网，装 Node.js 怎么办？**
在有外网的机器上到 nodejs.org 下载对应架构的 `.msi`（Windows）或 `.tar.xz`（Linux），拷过去安装即可。
Node.js 安装包本身不需要联网。

**Q2：`npm ci` 报网络错误 / 卡在 `prisma generate`？**
见 2.3。用方案 A 直接绕开；或按 4.2 配引擎镜像。

**Q3：装依赖都成功了，但 `npm run build` 报找不到 Prisma Client？**
`postinstall` 的 `prisma generate` 没跑成功（多半就是引擎没下下来）。手动执行 `npx prisma generate`，
若仍失败按 2.3 处理。

**Q4：服务起不来，报 `EADDRINUSE`？**
端口被占用：`netstat -ano | findstr :3000` 找到末尾 PID，`taskkill /F /PID <PID>`；
或改 `.env` 里的 `PORT=3001` 重启。

**Q5：本机能打开，同事打不开？**
先查 6.2 的防火墙规则是否已加，再确认给同事的 IP 是不是虚拟网卡地址。

**Q6：能删 `.next/cache` 吗？**
能。它是 `next build` 的编译缓存，只影响后续构建速度，`next start` 运行不需要它。
删掉能让交付包小 478MB。

**Q7：为什么包里不带 `.env`？**
`.env` 是**每台机器本地的配置**，且按项目安全约定不入库、不入交付包。目标机首次部署时从
`.env.example` 生成即可。

**Q8：内网里能用 PostgreSQL 吗？**
可以，但需要内网单独部署数据库实例。注意 SQLite 与 PostgreSQL 的迁移历史不通用，
切换属于一次性数据迁移动作，建议在尚未积累正式数据时完成。详见[部署指南第五节](./部署指南.md)。

**Q9：只用内网，代码能不能不放到 GitHub？**
可以。本文件描述的就是不依赖任何公网服务的部署路径；代码托管走内网 Git（方案 C）即可。
