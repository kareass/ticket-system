# 需求ID 改为选填 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让「需求ID」在手工新建/编辑需求时可留空（工单转需求仍必填），且**全程不丢失、不错漏任何一条既有数据**。

**Architecture:** schema 由 `String @unique` 改为 `String? @unique`（SQLite 会重建 `Requirement` 表）；写入侧把空串归一为 `NULL`（SQLite 唯一索引允许多条 NULL 但只允许一条空串）；出参侧用既有的 `clean()` 把 null 归一为 undefined。`work-order-sync.ts` 一行不改。

**Tech Stack:** Next.js 14 / TypeScript 5 / Prisma 5 / SQLite 3.35 / antd 5

**设计依据：** `docs/superpowers/specs/2026-09-17-需求ID改为选填-design.md`

## Task 5: PUT 的三态语义

**Files:**
- Modify: `src/app/api/requirements/[id]/route.ts:73-80`

- [ ] **Step 1: 把「不能为空」改成「空串 = 清空」**

第 73-80 行附近：


改为：

```ts
  if (body.requirementId !== undefined) {
    // 三态语义（与项目既有契约一致）：
    //   undefined（未传）→ 不改该字段
    //   ""（显式清空）   → 落 null
    //   非空             → 改名；与现值不同才触发改名侦测
    const requirementId = asTrimmed(body.requirementId);
    if (requirementId) {
      data.requirementId = requirementId;
      if (requirementId !== existing.requirementId) newRequirementId = requirementId;
    } else {
      data.requirementId = null;
      // 注意：这里刻意**不**设置 newRequirementId —— 清空不应把来源工单上的

      // 且 newRequirementId 保持空串时，下方 `if (newRequirementId && ...)`
      // 也会因空串为假而自然跳过。
    }
  }
```
